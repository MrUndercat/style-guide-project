# Как внести изменения

## Ветки

Каждое изменение делается в отдельной ветке от `main`. Имя ветки
строится по схеме `<тип>/<краткое-описание>`: `feat/accessibility`,
`fix/glossary-typo`.

## Коммиты

Сообщение коммита пишется в формате `<тип>: <что сделать>` и
максимально коротко:

| Тип | Когда использовать |
| --- | --- |
| `feat` | Новый раздел или правило |
| `fix` | Исправление ошибки в тексте или настройках |
| `chore` | Настройка инструментов, CI/CD, зависимостей |
| `dev` | Служебные изменения в процессе разработки |

Пример: `feat: добавить раздел доступности`.

## Pull Request

1. Название Pull Request пишется в том же формате, что и коммит.
2. В описании указывается, что изменено и зачем.
3. Перед созданием Pull Request выполните `mkdocs build --strict`.
4. Pull Request объединяется после успешных проверок CI и одобрения
   рецензента.

## Новый раздел

1. Создайте файл в каталоге `docs`. Имя пишется латиницей в нижнем
   регистре через дефис.
2. Добавьте страницу в раздел `nav` файла `mkdocs.yml`.
3. Проверьте сборку и линтинг командами из [README.md](README.md).

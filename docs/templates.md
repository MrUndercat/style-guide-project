# Шаблоны

Раздел содержит шаблоны описания для каждого типа задачи. Скопируйте
шаблон в поле «Описание», заполните разделы и удалите подсказки в угловых
скобках.

## Как выбрать тип задачи

| Тип | Когда использовать | Кто обычно создаёт |
| --- | --- | --- |
| Epic | Крупная функция, которая делится на несколько историй | Владелец продукта |
| Story | Ценность для пользователя, которую можно показать на демо | Аналитик |
| Task | Техническая работа без видимой пользователю функции | Разработчик |
| Bug | Система ведёт себя не так, как описано в требованиях | Тестировщик, любой участник |
| Sub-task | Часть Story или Task, которую выполняет один человек | Исполнитель родительской задачи |
| Spike | Исследование, результатом которого является решение, а не код | Разработчик |

## Epic

Тема: существительное, описывающее функцию: «Онлайн-оплата заказа».

```markdown
## Цель
<Какую проблему пользователя или бизнеса решает эпик.>

## Объём
- <Что входит в эпик.>
- <Что не входит в эпик.>

## Метрика успеха
<Как измерить результат: показатель и целевое значение.>

## Материалы
- <Ссылка на требования, макеты, исследования.>
```

## Story

Тема: глагол в инфинитиве и результат: «Добавить фильтр заказов по
статусу».

```markdown
## История
Как <роль>, я хочу <действие>, чтобы <ценность>.

## Контекст
<Почему это нужно сейчас, текущее поведение.>

## Критерии приёмки
- [ ] <Проверяемое условие 1.>
- [ ] <Проверяемое условие 2.>

## Макеты и материалы
- <Ссылка на макет.>
```

## Task

Тема: глагол в инфинитиве и объект: «Обновить Spring Boot до версии 3.3».

```markdown
## Контекст
<Зачем нужна работа.>

## Что сделать
1. <Действие.>
2. <Действие.>

## Критерии готовности
- [ ] <Проверяемое условие.>

## Риски и ограничения
<Что может сломаться, на что обратить внимание.>
```

## Bug

Тема: «<Где>: <что происходит> <при каком условии>».

```markdown
## Окружение
- Стенд: <test / stage / prod>
- Версия сборки: <номер>
- Браузер или устройство: <название и версия>

## Предусловия
<Пользователь, данные, настройки.>

## Шаги воспроизведения
1. <Действие.>
2. <Действие.>

## Фактический результат
<Что происходит.>

## Ожидаемый результат
<Что должно происходить, со ссылкой на требование.>

## Частота
<Всегда / иногда (N из M попыток).>

## Вложения
<Снимок экрана, лог, запись экрана.>
```

## Sub-task

Тема: глагол в инфинитиве и конкретная часть работы: «Написать миграцию
таблицы orders».

```markdown
## Что сделать
<Одно-два предложения.>

## Критерий готовности
- [ ] <Проверяемое условие.>
```

## Spike

Тема: «Исследовать <вопрос>»: «Исследовать варианты кеширования каталога».

```markdown
## Вопрос
<Какой вопрос нужно закрыть.>

## Ограничение по времени
<Не более N дней.>

## Ожидаемый результат
<Решение, сравнение вариантов, прототип, документ.>

## Варианты для рассмотрения
- <Вариант 1.>
- <Вариант 2.>
```

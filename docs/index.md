# Стайлгайд по оформлению задач в Jira

Руководство описывает, как писать и оформлять задачи в Jira, чтобы любой
участник команды понимал, что нужно сделать, зачем и как проверить
результат, не задавая уточняющих вопросов автору.

## Область применения

Правила обязательны для всех задач проекта в Jira:

- эпиков (Epic);
- пользовательских историй (Story);
- задач (Task);
- ошибок (Bug);
- подзадач (Sub-task);
- исследовательских задач (Spike).

Правила распространяются на поля «Тема» (Summary), «Описание» (Description),
«Критерии приёмки», комментарии, метки, компоненты и связи между задачами.

## Для кого руководство

| Роль | Как использует руководство |
| --- | --- |
| Аналитик, владелец продукта | Создаёт истории и эпики по шаблонам |
| Разработчик | Создаёт технические задачи, оценивает и уточняет задачи |
| Тестировщик | Заводит ошибки по шаблону, проверяет критерии приёмки |
| Руководитель команды | Проверяет готовность задачи к взятию в спринт |

## Как пользоваться руководством

1. Перед созданием задачи выберите её тип и откройте
   [шаблон](templates.md) этого типа.
2. Заполните поля, сверяясь с разделами
   [«Стиль изложения»](style.md) и [«Оформление текста»](formatting.md).
3. Проверьте термины по [глоссарию](glossary.md).
4. Перед переводом задачи в статус «Готова к работе» пройдите
   [чек-лист](tips.md#checklist).

## Основные принципы

- **Самодостаточность.** Задача понятна без устных пояснений и переписки
  в мессенджере.
- **Проверяемость.** Результат описан так, что его можно проверить по
  критериям приёмки.
- **Единообразие.** Задачи одного типа выглядят одинаково и заполняются
  по одному шаблону.
- **Краткость.** В задаче нет лишнего текста: каждое предложение помогает
  выполнить или проверить работу.

!!! note "Если правила нет"
    Если ситуация не описана в руководстве, руководствуйтесь основными
    принципами и предложите новое правило через Pull Request в
    [репозиторий руководства](https://github.com/MrUndercat/style-guide-project).
